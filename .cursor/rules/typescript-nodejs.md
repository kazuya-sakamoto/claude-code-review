# TypeScript/Node.js プロジェクトのコーディングガイドライン

# CodeRabbit が自動的に読み込んでレビューに適用します

## プロジェクト特性

- ESM モジュール（"type": "module"）を使用
- TypeScript で型安全性を重視
- Node.js ランタイム環境
- tsx を使用したテスト実行

## 型安全性

- `any`型の使用は避ける。適切な型定義を推奨
- 型推論を活用しつつ、明示的な型定義も適切に使用
- ジェネリクスを活用して再利用可能なコードを書く
- 型ガードやアサーション関数を適切に使用

## エラーハンドリング

- 非同期処理には必ず try-catch を実装
- fetch API 使用時は HTTP ステータスコード（response.ok）のチェックを必須
- エラーメッセージは明確で具体的に
- エラーオブジェクトを適切に処理し、スタックトレースを保持

## API 設計

- fetch API 使用時は必ず HTTP ステータスコードをチェック
- リクエスト/レスポンスの型を明確に定義
- タイムアウト処理を考慮
- リトライロジックが必要な場合は実装

## テスト

- テストファイル（\*.test.ts）の品質も重視
- テストカバレッジを意識した実装
- 単体テスト、統合テストを適切に分離
- テストは明確で読みやすく、意図が分かるように

## コードの可読性

- 複雑なロジックには適切なコメントを追加
- 関数は単一責任の原則に従う
- マジックナンバーは定数として定義
- 長すぎる関数は分割を検討

## パフォーマンス

- 不要なループや非効率な処理を避ける
- 非同期処理を適切に並列化（Promise.all 等）
- メモリリークに注意（イベントリスナーの解除等）
- 不要な再レンダリングや再計算を避ける

## コーディング規約

- クラス名: PascalCase（例: `ApiClient`, `Calculator`）
- 関数名・変数名: camelCase（例: `fetchUser`, `userId`）
- 定数: UPPER_SNAKE_CASE（例: `MAX_RETRY_COUNT`）
- エクスポートは明示的に（`export class`, `export function`）
- 未使用の変数やインポートは削除

## 禁止事項

- `console.log`の本番コードへの混入（デバッグ用は削除）
- `debugger`ステートメントの残存
- `any`型の不適切な使用
- 未使用の変数、インポート、パラメータ
- コメントアウトされたコードの残存

## ベストプラクティス

- 関数のパラメータは 3 つ以下を目安に
- 早期リターンでネストを浅く保つ
- オプショナルチェーニング（`?.`）や Null 合体演算子（`??`）を適切に使用
- 配列操作は`map`, `filter`, `reduce`などの高階関数を活用
- 非同期処理は`async/await`を優先的に使用
